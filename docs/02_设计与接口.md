# 系统、数据库与API

## 结构与MongoDB选择

Python + FastAPI + Pydantic + PyMongo；自行实现问卷业务，不使用关系数据库或现成问卷框架。`auth`、`surveys`、`responses` 按职责分包，routes/models/service/repository分别处理HTTP、契约、业务和存取；`database` 管初始化与迁移，`core` 管配置/时间。`web/static/` 为原生模块化页面：api负责请求/会话，app负责入口/列表，editor负责题目/规则/设置，fill负责填写，results负责统计；与API使用同一Python服务。

用户、会话、问卷、答卷生命周期不同，分集合存储。问卷内嵌有序题目/选项/规则，适合一次读出配置和单文档编辑；答卷单独存，避免问卷数组无限增长。没有把所有数据塞进一个集合，也没有机械照搬关系表。统计从真实答卷聚合，不维护易失配的累计计数。

| 集合 | 主要内容 | 索引与理由 |
| --- | --- | --- |
| users，schema1 | ObjectId、username、username_key、password_hash、created_at | username_key唯一；Argon2id密码哈希 |
| sessions，schema1 | user_id、token_hash、created_at、expires_at | token_hash唯一；expires_at TTL=0，可独立撤销 |
| surveys，schema3 | owner_id、标题/说明、匿名/重复设置、deadline、状态、revision、有序questions、jump_rules、share_id、发布时间/关闭时间/创建更新时间、submission_serial、last_submission_at | owner_id/created_at/_id；字符串share_id部分唯一 |
| submissions，schema1 | survey_id、内部respondent_id、request_id、fingerprint、survey_revision、anonymous、single_response、submitted_at、submission_serial、path、answers | survey_id/respondent_id/request_id唯一；single_response=true时survey_id/respondent_id部分唯一；survey_id/submitted_at/_id分页 |

Schema定义在 `app/database/connection.py`、`app/surveys/schema.py`、`app/responses/schema.py`；strict/error且禁止多余字段。引用使用ObjectId，时间使用UTC/BSON毫秒。题目ID `q_<32位hex>`、选项ID `opt_<32位hex>`由服务端生成；改题干/选项标签/排序可保留身份。`schema_migrations`和`surveys_v*_backup_*`仅用于升级审计及原文保留。

## 配置、权限和状态

| type | 配置与回答要求 |
| --- | --- |
| single_choice | 2～50个选项；回答为本题单个选项ID |
| multiple_choice | 同上；min_selections默认0、max_selections默认null=选项数；min=max表示恰选；答案无重复并按选项原序保存 |
| text | min_length默认0、max_length默认1000，上限10000；按Unicode码点计数，保留有效首尾空格 |
| number | min_value/max_value可空，含端点；integer_only；仅有限JSON数值且在±10^15，拒绝bool/数字字符串；整数题接受1.0并保存为1 |

每卷最多100题/200条规则。标题1～200、说明≤5000、题干1～500、选项标签1～200；标签按NFKC+casefold去重。上下界须可满足；必答多选max=0、整数区间不含整数均拒绝。null/空白文本或单选/空多选数组视为未答：必答拒绝，选答存null；非空选答仍受上下界约束。这些具体上限及处理方式是工程约定。

账号名NFKC/strip后为3～32位ASCII字母/数字/下划线，唯一键忽略大小写。密码8～128字符、不全空白；Bearer原token只返回一次，数据库存SHA-256摘要。鉴权主动检查过期，不依赖TTL及时清理；错误响应不回显原输入或凭据。

管理操作绑定当前owner；他人和不存在的资源均404。草稿更新比较 `_id+owner_id+revision+draft`，成功revision加1，冲突409。题目替换只能复用本题optid；排序须为全部qid精确排列。

持久状态 `draft→published→closed`；发布前重验题目和规则，发布后冻结内容/配置，只能关闭、不重开。动态availability为draft/open/expired/closed；当前时间≥deadline即过期，不自动改版本或删除数据。分享链接仍需登录。

## 配置化跳转与提交

规则存于问卷，统一字段 `kind/source_id/target_id/operator`，target_id为后方qid或`end`；未命中默认下一题，多个命中按数组顺序取第一条。不支持回跳，避免循环。单选：choice/eq且一个option_ids；多选：eq=集合完全相等、contains_any=任一、contains_all=全部；数字：number及eq/ne/gt/gte/lt/lte/value。选答null不匹配任何条件，包括ne。没有按具体问卷硬编码。

配置及发布时检查题目/选项归属、类型、方向；改题、删题或排序使规则失效就拒绝，需先修改规则。示例：q1选“否”跳q3；q2包含A和B跳q4；q3数字<18结束。可直接运行demo复现这三类规则。

navigate输入 `{survey_revision, answers: {qid: value}}`，从第一题重算路径，遇到第一个未提供答案的题返回next_question_id；选答要显式null才继续。返回path、规范化answers、completed，不落库。用户改前题后应移除旧分支答案。

提交输入 `{survey_revision, request_id, anonymous, answers}`；request_id为8～64位字母/数字/下划线/连字符。后端重新计算完整路径并校验，只要求实际经过的必答题；拒绝未知题和路径外答案。允许省略经过的选答，保存为null。每份答卷保存版本、路径及规范化值，不能凭前端“已校验”标记绕过。

匿名仍须登录，且仅在allow_anonymous=true时可选；创建者接口把respondent置null，不暴露内部账号引用。内部仍保存respondent_id用于限次和重试，这是**对创建者匿名**，不是数据库不可追溯。禁重复时同账号至多1份，切换匿名不能绕过；允许重复时每个新request_id可另填一份。

同一账号/问卷/request_id及相同请求内容重放返回原回执200；内容不同409；首次保存201。对象键顺序不影响指纹，数组顺序属于内容。关闭/截止后可重取原回执，但不能新增答卷。客户端重试须保留原request_id与内容。

提交通过问卷单文档原子门控，检查published/版本/数据库时间截止条件并记录受理时刻，再插入答卷；关闭也更新同一问卷。**先受理的请求可在关闭后完成落库，先关闭则新请求410**。不声称standalone存在跨集合事务：门控后崩溃可能留下尝试序号空档，只有真实答卷计入统计；插入确认失败返回503，同请求重试可确认是否已保存。唯一索引处理并发重试/限次，不依赖“先查再插”保证。依据：[MongoDB原子性](https://www.mongodb.com/docs/manual/core/write-operations-atomicity/)、[NOW变量](https://www.mongodb.com/docs/manual/reference/aggregation-variables/)。

## 浏览器页面

首页 `/` 提供注册登录和本人问卷列表；`/#/surveys/{id}/edit` 提供题目/跳转/设置，`/#/surveys/{id}/results` 提供统计/答卷分页；`/survey/{share_id}` 提供填写。浏览器请求text/html只得到无业务数据的公共页面，JavaScript再带Bearer读取JSON；默认及application/json请求仍按旧API鉴权，Vary: Accept区分响应。没有改业务数据结构或替换原接口。[FastAPI响应机制](https://fastapi.tiangolo.com/advanced/custom-response/)。

填写由navigate返回下一题；回退修改会丢弃后续旧分支答案，再由服务端重算。最终提交使用固定request_id；网络/503未确认时锁定内容，重试同一请求。当前页签的sessionStorage仅暂存令牌、未确认请求和成功回执，按账号/问卷隔离；刷新可继续确认，正式业务数据仍以MongoDB为准。退出或过期不再显示管理数据；过期后登录回到原分享地址。

用户文字转义显示，不作为HTML执行；页面使用本地CSS/JS，无CDN/内联脚本；CSP仅允许本源脚本。异步响应到达时核对当前页面及分页状态，避免退出或切页后旧响应覆盖新页面。设置未保存时切页会提示，发布需先保存设置。已验证桌面及390px手机布局。

## API速查

下表业务API除注册/登录/健康外均需Bearer，公共HTML和静态资源不含业务数据。准确模型以 `/openapi.json` 为准。

| 方法与路径 | 输入→结果 |
| --- | --- |
| POST /api/auth/register；/login | username/password→201用户；200令牌/过期/user |
| GET /api/auth/me；POST /api/auth/logout | 当前用户200；注销204 |
| POST /api/surveys；GET /api/surveys | 标题和可选设置→201草稿；本人列表200 |
| GET/PATCH /api/surveys/{id} | 详情；expected_revision+元数据→200 |
| POST /api/surveys/{id}/questions | 题目模型，query expected_revision→201 |
| PUT/DELETE /api/surveys/{id}/questions/{qid} | 替换/删除，query expected_revision→200 |
| PUT /api/surveys/{id}/question-order | question_ids，query expected_revision→200 |
| PUT /api/surveys/{id}/rules | expected_revision、rules→200详情 |
| POST /api/surveys/{id}/publish；/close | expected_revision→200详情 |
| GET /survey/{share_id} | JSON请求：分享内容/规则/配置/版本→200，不含owner；浏览器HTML请求：填写页面 |
| POST /survey/{share_id}/validate | question_id、value→200规范化单题答案，不存储 |
| POST /survey/{share_id}/navigate | survey_revision、answers→200路径预览 |
| POST /survey/{share_id}/responses | 完整提交→201回执，重试200 |
| GET /api/surveys/{id}/responses | 本人问卷答卷列表，匿名隐藏身份 |
| GET /api/surveys/{id}/statistics | 整卷统计 |
| GET /api/surveys/{id}/statistics/{qid} | 单题统计及文本/数字内容分页 |
| GET /health/live；/health/ready | 进程/数据库就绪200，数据库故障503 |

分页offset=0..2147483647、limit=1..100，默认0/20；版本为1..2147483647。常见错误：401未登录，404未知/无管理权限，409版本/状态/重复/请求冲突，410已关闭或截止，422输入/规则/答案非法，503数据库故障。答案422含 `{question_id,code,message}`，不回显原值；分享、答卷、统计响应no-store。

统计单位为**份数/选择次数**，允许重复时同账号多份分别计数。total_responses只数已保存答卷；visited_count数经过本题的答卷，answer_count排除null，被跳过不算回答；选项含零次数，数字平均值排除未答，无数值时null。整卷用MongoDB `$facet` 对同一批输入生成总数/题目/选项统计；单题内容和答卷按时间及_id降序分页。活跃提交期间不同请求/分页可能变化，不承诺跨请求快照。

## 数据保留与迁移

停API→dry-run→原文备份和in_progress审计→只允许已知新旧schema→补字段→逐文档核对→收紧schema→completed。v1→v2仅补分享/发布时间/关闭时间；v2→v3仅补空jump_rules、submission_serial=0、last_submission_at=null。ID、题目、业务revision、原时间及用户/会话保留。首次备份不覆盖，中断可续跑，未知结构拒绝；不以清库代替升级。

原v1→v2脚本及回归保留，新旧版本使用同一迁移引擎。当前4份旧v2问卷已迁移，旧v1备份也未变；本地BSON集中存backups。后续第二阶段仍在本结构上修改并记录原因、数据/代码变化、兼容性及旧功能回归。
