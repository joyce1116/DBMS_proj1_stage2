# 系统、数据库与 API

## 结构

Python + FastAPI + PyMongo，自行实现问卷业务。`app/auth/` 处理账号，`app/surveys/` 处理问卷；各自的 routes/models/service/repository 分别负责 HTTP、数据模型、业务和存取。`app/database/` 初始化/迁移，`app/core/` 管配置/时间，`app/main.py` 为入口。移动原模块并更新导入，保留原实现和接口，没有另建系统。

依 Word 要求，所有业务数据存 MongoDB，不使用关系库或现成问卷框架。用户和会话生命周期不同，分集合避免无限扩张用户文档；题目与选项随问卷一起读写，数量有限，内嵌有序数组适合 MongoDB 文档和单文档原子编辑，不机械照搬关系表。尚未创建回答集合。

## 已落地的 MongoDB 设计

| 集合 | 主要字段 | 索引/理由 |
| --- | --- | --- |
| users | ObjectId、username、username_key、password_hash、created_at、schema_version=1 | username_key 唯一；Argon2id 密码哈希 |
| sessions | ObjectId、user_id、token_hash、created_at、expires_at、schema_version=1 | token_hash 唯一；expires_at TTL=0，独立撤销/过期 |
| surveys | ObjectId、owner_id、title、description、allow_anonymous、allow_repeat、deadline、status、revision、questions、share_id、published_at、closed_at、created_at、updated_at、schema_version=2 | owner_id/created_at/_id 排序索引；share_id 字符串部分唯一索引，允许多个 null 草稿 |

集合使用 strict/error JSON Schema，禁止多余字段，定义在 `app/database/connection.py`、`app/surveys/schema.py`。用户/会话引用用 ObjectId，日期为 UTC 毫秒。题目 `q_<32位hex>`、选项 `opt_<32位hex>` 服务端生成，改名和排序可保留 ID，后续回答/跳转按 ID 引用。每卷最多 100 题。

`schema_migrations` 保存结构变更审计，`surveys_v1_backup_*` 保存迁移前原文。它们不是统计或回答集合。

## 题型配置与业务规则

| type | 配置 |
| --- | --- |
| single_choice | required、2–50 个选项；label 1–200 字符，NFKC+casefold 后不得重名 |
| multiple_choice | 同上；min_selections 默认 0，max_selections 默认 null=选项数；0≤min≤max≤选项数，相等表达恰选；必答不能 max=0 |
| text | 填空子型；min_length 默认 0，max_length 默认 1000（上限 10000），min≤max |
| number | 填空子型；min_value/max_value 可空，有限数值且在 ±10^15；integer_only 为 true 时区间必须含整数 |

题干 1–500 字符；问卷标题 1–200、说明至多 5000。布尔、整数等严格检查类型，拒绝无效上下界。这些上限是工程约定，原文未逐项规定。当前配置校验和实际回答校验的完成状态见导航与测试记录。

用户名先 NFKC/strip，3–32 位 ASCII 字母/数字/下划线，唯一键忽略大小写；密码 8–128 字符、不全空白，保留有效首尾空格。登录随机 Bearer token 仅返回原值，MongoDB 只存 SHA-256 摘要；鉴权主动判断过期，不能等待 TTL 清理。响应不返回密码哈希，422 移除原始输入以免回显密码。

问卷读取/写入都绑定当前 owner_id；修改使用 `_id+owner_id+revision+draft` 原子条件并递增 revision，冲突 409。题目替换保留 qid，携带本题旧 optid 可保留选项身份，省略表示新增；排序必须是全部现有 qid 的精确排列。

持久状态 `draft → published → closed`。发布需非空且配置合法、未截止；发布后冻结全部内容，只允许关闭、不重开（工程约定）。动态 availability 为 draft/open/expired/closed，is_open 仅 open 为真；UTC 当前时间≥deadline 即过期，不改持久状态/版本、不删除问卷。分享仍须登录，匿名设置不免登录。

## 当前接口

除注册/登录/健康外均需 Bearer。成功对象以 `/openapi.json` 为准确契约。

| 方法/路径 | 输入与结果 |
| --- | --- |
| POST /api/auth/register | username/password →201 公开用户 |
| POST /api/auth/login | 同上 →200 token、到期、user |
| GET /api/auth/me；POST /api/auth/logout | 当前用户 200；撤销当前会话 204 |
| POST /api/surveys | title 及可选元数据 →201 空草稿 |
| GET /api/surveys；GET /api/surveys/{id} | 本人列表（offset 0..2147483647、limit 1..100）/详情 200 |
| PATCH /api/surveys/{id} | expected_revision+至少一个元数据 →200；仅 deadline 允许 null |
| POST /api/surveys/{id}/questions | 完整题目，query expected_revision →201 |
| PUT/DELETE /api/surveys/{id}/questions/{qid} | 替换/删除，query expected_revision →200 完整问卷 |
| PUT /api/surveys/{id}/question-order | question_ids，query expected_revision →200 |
| POST /api/surveys/{id}/publish；/close | expected_revision →200 状态变更 |
| GET /survey/{share_id} | 已登录只读分享 200/no-store，仅内容和配置；未知404、关闭/截止410 |
| POST /survey/{share_id}/validate | question_id/value →200规范化答案，或422含题目ID/错误码；只校验，不保存 |
| GET /health/live；/health/ready | 进程/数据库状态，200；数据库不可用503 |

公共错误：未认证401，非本人/不存在管理资源404，版本或状态冲突409，非法请求422。分享响应排除创建者、分享字段、管理状态及账号信息，保留 revision 供后续提交关联。当前分享是 JSON，不是填写页面。

## 实际回答校验

`app/surveys/validation.py` 提供纯函数，接口从已发布问卷读取真实配置，不接受客户端伪造 required/范围。未知题目404，未登录401，关闭/截止410。错误422返回 `detail: {question_id,code,message}`，不回显原答案。

单选必须是本题选项ID；多选必须是无重复的本题ID数组并满足数量，返回时按选项原序排列。文本按Python Unicode码点计数，保留有效首尾空格。数字只接受有限JSON数值、拒bool/数字字符串/超±10^15，边界包含端点；整数题接受1.0并规范为1，拒绝小数。

null表示未答；文本/单选空白串、多选空数组也视为未答：必答拒绝，非必答返回null。非必答多选为空可跳过，非空仍须满足min。数字空字符串属于类型错误。上述为本轮明确的输入约定。

当前只判断一道题；没有保存答卷、执行跳转或保证提交有效。后续跳转决定实际路径，提交端再复用此函数校验经过的题目并检查开放状态，不能信任前端的“校验成功”。

## v1→v2 迁移及后续保留

停止 API →只读预检 →原文备份与 in_progress 审计 →临时允许已知 v1/v2 →只补三项 null 发布字段及 schema_version=2 →逐文档核对 →收紧 v2 →completed。保留 ID、题目、revision、原时间，原用户/会话不变。完成后重跑为 already_v2，中断可续跑；未知结构拒绝，不自动清库。standalone 上这是离线迁移，不声称跨操作事务或在线迁移。

两份旧草稿已按此流程保留，完整原文备份继续在 MongoDB；本地导出副本与旧文档集中放 `backups/`，不随代码上传。后续第二阶段收到真实变更后，仍在本代码上增量修改并记录结构、兼容性和回归，不能推倒重做。
