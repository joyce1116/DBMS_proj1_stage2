本次后端范围包括创建者发布与关闭自己的问卷、UTC 截止判断，以及 `/survey/<share_id>` 的登录只读访问。管理列表、详情和编辑仍只属于创建者；拿到分享链接的其他已登录用户可通过独立分享接口读取问卷内容。所有接口复用原有登录会话，不新增账号系统。

持久状态为 `draft`、`published`、`closed`。创建者响应补充动态 `availability`（`draft`、`open`、`expired`、`closed`）和 `is_open`；已发布问卷在当前 UTC 时间大于或等于截止时间时过期，不后台改库、不因读取改变 revision。发布后冻结全部题目和元数据，只能关闭，不能重开；这是为保持发布内容稳定作出的工程约定，并非原文逐字要求。

发布生成 32 位随机分享 ID，返回相对路径 `share_url: /survey/<share_id>`。分享接口要求登录，即使 `allow_anonymous: true`，未登录也返回 401；未知链接返回 404，关闭或已截止返回 410。成功只返回 `id`、标题、说明、匿名/重复设置、截止、revision 和题目，不返回创建者、分享标识、状态、schema 或账号资料。revision 是结构引用版本，供后续提交关联，并非秘密信息。

`allow_anonymous`、`allow_repeat` 仍只保存设置，没有匿名作答或重复提交限制。**网页、实际填写、回答校验、配置化跳转、提交与统计本轮仍未实现。** `/docs` 是 API 调试文档，不是最终问卷网页。

`surveys` 从 schema v1 增量升级为 v2，补充 `share_id`、`published_at`、`closed_at`，通过显式迁移、备份与审计保留旧数据，不清库。当前两份旧草稿已迁移并逐字段核对，原 ID、题目、revision 和时间保留；重跑为 already_v2。本轮全量 **127 项通过**（原有 83 + 新增 44），保留 1 条既有弃用警告；实际 HTTP 演示通过。详细证据见 `10_survey_lifecycle_tests.md`。

## 里程碑 1 沿用的实现选择

以下是上一轮 AI 根据需求提出并落实、本次继续沿用的选择，不是原文逐字规定，也未经过用户逐项确认：

- 用户名先做 NFKC 规范化、去除两端空白，再限制为 3–32 个英文字母、数字或下划线；显示保留大小写，唯一键忽略大小写。暂不支持中文用户名。
- 注册密码为 8–128 个字符，不能全为空白；原文未规定复杂度。密码使用 Argon2 哈希。
- 使用随机 opaque Bearer token；原始 token 仅在登录响应返回，数据库只保存 SHA-256 摘要。
- 默认会话有效期 86400 秒，可配置；退出时删除当前会话，其他会话不自动退出。
- 用户和会话使用稳定 `ObjectId`、UTC 时间及 `schema_version: 1`。
- 数据库使用严格 JSON Schema validator；启动时保留现有集合，不静默覆盖不同版本的 validator。
- MongoDB TTL 索引用于清理过期会话，但读取会话时仍主动检查过期时间，不能依赖后台清理的及时性。

这些选择均应结合实际测试评估。用户亲自修改了什么、独立设计了什么，尚待本人核实，不能在报告中代为认领。

## 里程碑 2 草稿设计与保留旧成果（历史）

新增 `surveys`，不把问卷数组追加到用户文档。问卷保存创建者 `owner_id`，其值来自当前认证用户；不接受客户端借此指定或变更创建者。当前问卷数据包括元数据、`status: draft`、`revision`、创建/更新时间、`schema_version: 1` 和有序 `questions` 数组。题目随问卷读取和修改，因而本次采用内嵌结构；后续回答不在本次创建集合或接口。

题目 ID 为服务端生成的 `q_` 前缀加 UUID，选项为 `opt_` 前缀加 UUID。编辑保留题目 ID；编辑选项时提交已有 ID 可保留该选项身份，未提供 ID 的选项视为新增，不能借用其他题目的选项 ID。排序只改变顺序，不重建题目。后续跳转与回答可据此引用稳定身份。

本次工程约定还包括：`allow_anonymous`、`allow_repeat` 默认 false；创建或修改为非空 `deadline` 时必须提供带时区的未来时间，保存为 UTC 毫秒；截止后如何执行留待发布模块。题型用 `single_choice`、`multiple_choice`、`text`、`number` 区分；多选约束字段为 `min_selections`、`max_selections`，文本为 `min_length`、`max_length`，数字为 `min_value`、`max_value`、`integer_only`。数字边界只允许有限 JSON 数字且范围为 ±10^15，不把布尔或字符串当作数字。每份问卷最多 100 题，选择题 2–50 个选项。这些限制不是原文逐字要求。

所有草稿修改要求 `expected_revision`。数据库更新同时匹配问卷 ID、创建者、`status: draft` 及旧 `revision`，成功后原子递增版本；旧版本或并发冲突返回 409，调用方应重取后再编辑。此处只处理草稿编辑冲突，不代表已实现多人作答。

本次保留 `users`、`sessions` 的原 schema、账号接口和已有数据；仅增加 `surveys` 初始版本及其索引，没有改变旧集合结构，因此没有执行数据迁移。初始化继续核对现有 validator，不清库或静默覆盖。`schema_version: 1` 是版本标记，不等于已有迁移框架；后续确需改结构时仍须显式迁移并验证兼容性。

## 里程碑 3 生命周期与兼容增量

沿用已有路由、服务、仓储和题目模型，不重写账号或草稿功能。新问卷结构为 `surveys.schema_version: 2`，在旧结构上补充 `share_id`、`published_at`、`closed_at`；旧草稿的这些字段补为 null。迁移不重生成问卷、题目、选项或创建者身份，不借迁移制造一次业务编辑。两份旧草稿及原账号数据已核对保留，备份和审计保存在 MongoDB，具体命令和结果见 `10_survey_lifecycle_tests.md`。

发布和关闭均要求创建者身份与 `expected_revision`，通过单文档原子状态/版本比较防止覆盖并发编辑。发布冻结全部可编辑内容，关闭只改变生命周期相关字段及业务 revision；截止状态在读取时计算，不因过期创建额外编辑。分享路径在发布时建立，草稿没有开放入口；分享响应采用独立最小结构，管理权限不随链接转移。

这次迁移属于第一阶段内的模型迭代，不代表收到或完成了第二阶段需求。显式保留旧模型的稳定身份、旧数据及账号/草稿接口，是以后继续扩展的基础，不能提前声称已经证明所有未知需求都兼容。
