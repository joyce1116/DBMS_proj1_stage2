# 运行与复现

在当前项目根目录执行，无需复制到其他目录。实测：Windows PowerShell、Python 3.13.9、MongoDB 6.0.29；FastAPI 0.143.1、PyMongo 4.19.0，全部版本固定在 `requirements.txt`。下列运行命令使用 `-B` 避免生成源码缓存。

## 1. 准备 Python（已有 .venv 可跳过）

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

无需激活环境。可选复制 `.env.example` 为 `.env`。默认配置：`MONGO_URI=mongodb://127.0.0.1:27018`、`MONGO_DB=survey_phase1`、`MONGO_TIMEOUT_MS=3000`、`SESSION_TTL_SECONDS=86400`。环境变量优先；不上传 `.env`。

## 2. 终端 A：启动 MongoDB

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_mongo.ps1
```

需要已安装且 PATH 中可找到 `mongod`。数据保存在当前项目 `.runtime/mongo-data`，仅监听本机 27018；按 Ctrl+C 停止，保留数据。端口被占用时先确认现有实例，不随意终止进程。

## 3. 终端 B：初始化并启动后端

```powershell
.\.venv\Scripts\python.exe -B -m scripts.init_db
.\.venv\Scripts\python.exe -B -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

当前开发库已是 schema v2，新库直接初始化。**仅接续旧 v1 库时**，在 API 停止、MongoDB 运行的情况下，先执行以下两行，再初始化：

```powershell
.\.venv\Scripts\python.exe -B -m scripts.migrate_surveys_v2 --dry-run
.\.venv\Scripts\python.exe -B -m scripts.migrate_surveys_v2
```

迁移先在 MongoDB 备份并记录审计，保留原数据；可重跑。未知 schema 会拒绝，不能清库解决。详情见文档 02。

## 4. 终端 C：演示或测试

```powershell
# 实际 HTTP 演示：需要 A、B 均运行；会保留一个演示账号和关闭的问卷。
.\.venv\Scripts\python.exe -B -X utf8 -m scripts.demo

# 全部自动测试：仅需 A，测试自行创建应用及独立随机测试库。
.\.venv\Scripts\python.exe -B -m pytest -q

# 离线校验：不需要 A、B。
.\.venv\Scripts\python.exe -B -m pytest -m 'not integration' -q
```

API 交互文档：`http://127.0.0.1:8000/docs`，账号登录后用其 token 点 Authorize。接口 JSON 为 `/openapi.json`。`/docs` 默认 UI 需要外部 CDN；Python 演示不依赖它。当前没有用户网页。

演示依次创建四种题目、发布、校验四种实际回答、拒绝超范围年龄、关闭并退出，不打印密码/token；只保留演示账号和问卷，不保存答案。只测本轮回答校验可执行 `python -B -m pytest tests/test_answers.py -q`（用虚拟环境的 Python）。

## 5. 上传范围

直接使用当前项目里的 `app/`、`scripts/`、`tests/`、`docs/`、`requirements.txt`、`pytest.ini`、`.env.example`。不上传 `.git/`、`.venv/`、`.runtime/`、`backups/`、任何 `__pycache__/` 和实际 `.env`；不另建 `submission/`。

先停止终端 B，再停止 A。数据库数据、迁移审计和备份留在本地；不要把运行目录当作作业代码上传。
