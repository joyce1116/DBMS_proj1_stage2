001. 项目：基于 MongoDB 的问卷系统开发

002. 一、项目目标

003. 本项目要求开发一个简化版的在线问卷系统，功能类似于“问卷星”或 Google Forms。

004. 系统应允许注册用户创建问卷，并通过URL分发问卷，其他用户可以填写问卷，系统可以统计问卷结果。

005. 本项目重点考察：

006. MongoDB 数据库设计能力 

007. 后端程序设计能力 

008. 数据结构与业务逻辑建模能力 

009. 条件逻辑与跳转逻辑的实现能力 

010. 使用 AI 编程工具的能力与规范 

011. 本项目不要求复杂界面，可以使用简单网页。

012. 评分重点：

013. 数据库设计 + 后端逻辑 + 文档质量 + AI使用过程说明

015. 二、项目说明

016. 本课程项目将模拟真实互联网应用开发的过程。在实际的软件开发中，用户需求往往不是一次性确定的，而是会随着使用过程不断增加和变化。开发者通常需要在已有系统的基础上进行修改和扩展，而不是每次都重新设计和实现整个系统。

017. 为了让大家体验这种真实的软件开发过程，本项目分为 两个阶段 完成。

019. 第一阶段：根据初始需求完成系统设计与实现

025. 完成必要的测试 

026. 编写项目文档 

027. 提交完整的项目报告

189. 初始用户需求

190. 一、用户账号功能

191. 系统需要支持用户注册和登录。

192. 用户希望能够：

193. 注册账号 

194. 登录账号 

195. 使用自己的账号创建问卷 

196. 查看自己创建的问卷 

197. 查看问卷的统计结果 

198. 每个用户至少需要有：

199. 用户名 

200. 密码 

201. 注册时间 

202. 用户登录后，应只能看到自己创建的问卷。

204. 二、问卷创建与管理

205. 用户希望能够创建问卷。

206. 创建问卷时可以填写：

207. 问卷标题 

208. 问卷说明 

209. 是否允许匿名填写 

210. 用户希望能够：

211. 查看自己创建的问卷列表 

212. 发布问卷 

213. 设置问卷截止时间

214. 关闭问卷 

215. 每个问卷都应该有一个可以访问的链接，例如：

216. /survey/xxxxxx

217. 用户可以把这个链接发给别人，让别人填写问卷。

218. 填写问卷的人需要先登录。

220. 三、问卷中的题目

221. 一个问卷可以包含多个题目。

222. 用户希望在问卷中添加不同类型的问题。

223. 系统至少需要支持以下三种题型。

225. 1. 单选题

226. 示例：

227. 你的性别

228. 男 

229. 女 

230. 其他 

231. 用户希望能够：

232. 设置选项 

233. 设置是否必须回答 

234. 如果是必答题，填写问卷时必须选择。

236. 2. 多选题

237. 示例：

238. 你喜欢的水果

239. 苹果 

240. 香蕉 

241. 西瓜 

242. 葡萄 

243. 用户希望可以限制选择数量，例如：

244. 至少选择 2 个 

245. 最多选择 3 个 

246. 必须选择 2 个 

247. 系统在填写时需要检查是否符合要求。

249. 3. 填空题

250. 填空题可以是文字或数字。

251. 用户希望可以创建：

252. 文本填空 

253. 数字填空 

254. 对于文本填空，希望可以限制：

255. 最少输入多少字 

256. 最多输入多少字 

257. 对于数字填空，希望可以限制：

258. 最小值 

259. 最大值 

260. 是否必须是整数 

261. 例如：

262.    年龄：必须为整数，且在0~120之间

263.    手机号：必须为整数

264. 填写时系统应检查是否合法。

266. 四、题目跳转功能

267. 用户希望问卷可以根据回答情况跳转到不同题目。

268. 例如：

269. 如果第1题选 A → 跳到第5题如果第1题选 B → 跳到第3题

270. 用户希望可以设置：

271. 根据单选结果跳转 

272. 根据多选结果跳转 

273. 根据数字填空内容跳转 

274. 填写问卷时，系统应自动跳到对应题目。

275. 用户不希望跳转写死在程序里，而是可以在问卷中设置。

277. 五、填写问卷

278. 填写问卷的人可以通过问卷链接进入问卷。

279. 填写时希望：

280. 按顺序回答问题 

281. 根据规则跳转 

282. 如果填写不符合要求，系统提示错误 

283. 填写完成后可以提交 

284. 每次填写都应该被保存。

285. 系统需要支持：

286. 多人同时填写 

287. 匿名填写 

288. 同一个人填写多次（如果允许） 

290. 六、查看统计结果

291. 创建问卷的人希望可以查看统计结果。

292. 统计结果至少包括：

293. 单选题

294. 每个选项有多少人选择 

295. 总共有多少人回答 

296. 多选题

297. 每个选项被选择多少次 

298. 填空题

299. 可以查看所有填写内容 

300. 如果是数字，可以查看平均值 

301. 用户希望能够：

302. 查看整个问卷的统计 

303. 查看某一道题的统计 

304. 统计结果应该根据已经填写的数据自动生成。
