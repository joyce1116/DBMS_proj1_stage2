# 第一阶段项目报告草稿

## 项目目标与完成范围

按Word开发基于MongoDB的简化问卷系统，Python实现，不用关系数据库或现成问卷框架。重点为MongoDB建模、后端、配置化逻辑、测试和真实AI过程。

当前后端已覆盖账号、本人问卷管理、单选/多选/文本/数字题、发布/关闭/截止、登录分享、配置化跳转、填写校验/提交、匿名与限次、整卷及单题统计。依用户最新“除了前端都做完”完成本轮；**未实现前端，不能称整个第一阶段已经完成**。所有材料为Markdown，未写README。

## 系统与MongoDB设计

FastAPI/Pydantic、业务服务和PyMongo仓储分层，按auth/surveys/responses/database/core分包。用户/会话分开便于独立过期和撤销；题目、选项、规则内嵌问卷以匹配整体读写；答卷独立集合避免问卷无限增长。全部业务数据落MongoDB，使用ObjectId引用、UTC毫秒时间、strict Schema和唯一索引，不将所有数据放一个集合，不机械拆成关系表。

稳定题目/选项ID承接编辑、规则和答案引用；草稿以revision原子比较更新，发布后冻结。schema_version独立表达结构版本；显式迁移先备份和审计，再补字段，不修改原业务版本/时间/ID。本轮4份旧问卷增量升级到v3，账号和旧备份保留。

完整字段、索引、接口与边界约定集中见 [设计与接口](02_设计与接口.md)，复现见 [运行说明](01_运行说明.md)，不在报告重复完整清单。

## 跳转与校验设计

规则随问卷保存，引用qid/optid：单选eq，多选集合相等/任一/全部，数字六种比较。按配置顺序首命中，只向后或结束，未命中顺序前进；编辑/发布时检查关系与方向，避免失效引用和循环。后端同一引擎负责逐题预览和最终提交，不信任客户端路径；跳过的必答不强制填写，拒绝路径外旧答案。

配置及回答双层校验：必答、选项归属/重复、选择数、文本长度、有限数值/整数/范围；选答未填存null，多选按原序规范化。匿名仍登录，内部账号用于限次，创建者不见身份。唯一索引保护并发限次/请求重试，同请求200原回执，新答卷201。

standalone没有跨集合事务，因此明确以问卷原子门控时刻为受理点：先受理可在关闭后写完，先关闭/已截止则410。门控后失败可能留技术序号空档；只数真实答卷，503后的同请求重试用于确认保存结果。统计用MongoDB聚合生成份数、选项次数、填空内容和数字均值，空值/跳过不污染均值。
