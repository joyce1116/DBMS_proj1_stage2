## 可复现的自动用例

公共步骤：测试框架连接真实 MongoDB → 新建专属测试库 → 进入 `TestClient(create_app(settings))`，执行应用实际初始化 → 发送 HTTP 请求 → 查询真实库断言结果 → 关闭应用 → 清理该测试库。不是内存模拟数据库，不使用 SQLite。

账号测试的常用输入为 `Alice_01` / `correct horse 42`；这些是专用测试数据，不是用户真实凭据。每个用例都使用独立数据库。

## 失败、修复和复测

首次自动化测试有 35 项：28 通过、7 失败。

- 5 个失败来自应用的同一问题：注册响应直接返回带微秒的时间，MongoDB BSON date 保存到毫秒，随后登录/me/应用重建读取到的注册时间变化。修复 `app/services.py`，新增 `mongo_utc_now()`，生成用户和会话时间时统一毫秒精度。原用例保留，修复后全部通过。
- 另 2 个是测试自身错误：测试把英文错误类型中的 `input`/`short` 字样误认成泄露输入。修改为检查错误对象只含 loc/msg/type，并使用不容易与错误文案碰撞的短密码 `s3cr!`。没有削弱应用的密码保护，也没有修改应用去迎合错误断言。
- 初次 pytest 缓存写入遭 Windows 沙箱权限拒绝，禁用仅用于加速的缓存插件，并清理本轮生成的临时目录。

修复后的 35 项先全部通过；再加入 BSON 类型拒绝、旧 schema 冲突保护两个集成用例，最终主代理完整复测为 **37 passed, 1 warning in 7.30s**。

代码审查子代理另在自己创建的独立随机测试库里检查了孤立 Unicode 代理字符作为密码的输入，返回安全 422；其测试库已清理。该检查不计入上述 37 项，也不扩大为全部异常输入均已验证的结论。
